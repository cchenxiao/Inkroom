# 粘贴文本识别风格

入口：**创作准备 → 风格 → 从一段文字识别风格**。可以先分析文本，不必先填作品名或选方向；只有“导入风格编辑器 → 确认并保存”需要当前有效的作品方向。

## 本轮可用流程

1. 粘贴 80–30,000 个 Unicode 字符，可选填片段名。
2. 点“识别这段文字的风格”，提交独立异步任务。离开页面后仍可查看最近 5 次记录。
3. 查看观察、原文依据、表达建议和不确定性；必要时展开模型阅读范围、完整原文、调用记录。
4. 导入风格编辑器，改写锚文本、核对视角/时态与软目标，再人工采用。原文、原始分析和作者风格档案分别保存。

**文本不是作品名**：原先“参考作品名称 + 参考维度”继续保存线索；此入口真正接收参考文本，不联网检索，也不声称已读过整部书。

## 原文有多长，模型看了多少

全文先做本地句长统计。最多 3,000 字时全部供模型分析；超过时取首、中、尾各 1,000 字。界面明确显示总字数、模型阅读字数和原文范围（Unicode 下标，左闭右开；页面从第 1 字起显示）。全文、摘要 hash、取样和统计一起冻结。

超过 30,000 字会拒绝并保留输入，不静默截断。没有强行提高调用预算或后台发起很多模型调用；取样可能漏掉局部文风，用户可以换一段材料重试。默认模型输出和 token 预算沿用本地配置，约束超限会报失败，不自动扩大花费。

## Agent 技术

```text
作者原文 → 字数校验 → 冻结全文 + 取样 + 全文程序统计
          → style_analyst.v1 → Guard → Provider → Schema/引用校验
          → 带证据的观察 + StyleRules 草稿 + 锚文本摘录
          → 作者编辑 → 版本事务 → 已采用 StyleProfile
```

- `style_analyst` 是只读分析角色，不能续写、确认风格或写入作品事实。
- 观察维度为句式、节奏、对白、叙述距离、意象/感官、幽默/反差；只生成有依据的 1–6 项，不为凑齐六项伪造特征。
- 每项保存 sampleIndex 和逐字 quote，程序检查引用必须出自模型实际可见片段。建议锚文本也必须是片段原文。引用存在不等于解释一定正确，解释仍需作者判断。
- observed/tentative 是观察与推测的区分，不是校准过的置信度。句长由程序计算；对白占比目标、幽默及表达建议是候选，不伪造精确审美分数。
- 模型只拿到取样片段，全文只用于本地保存和统计；提示词隔离材料内指令。风格建议不得搬运参考文本中的人物、事件、世界规则。
- 采用保留 `analysisId/analysisVersion`；编辑既有风格另保留 `sourceStyleVersion`。分析不绑定某一方向，采用事务则绑定当时有效的立意/方向/风格版本，409 不覆盖作者文字。
- 不进入正文、Bible、向量索引或角色“已知”。下阶段 Planner 只读取作者确认后的规则，不读取参考原文或锚文本。

## API（独立 Go 规划接口）

- `GET /planning/style-analyses`：最近 5 条 StyleAnalysisJob，含原文快照、取样范围、统计、结果、调用记录。当前仅 zhuoliu/main。
- `POST /planning/style-analyses`：`{requestId,title,text}` → 202；相同 ID 和原文返回原任务，改变材料不能复用 ID。请求体限 256 KiB，解码后另验 30,000 字上限。
- `POST /planning/style-selection`：沿用原采用契约，新增 `analysisId/analysisVersion`；分析任务需 completed，不能同时声称来自试笔 job。编辑已有风格时来源必须与原档案一致。

分析每作品同时最多一条任务；2 分钟整体期限、最多 3 次调用（包括受限重试/结构修复）。进程重启将未完成任务记为 interrupted，不自动重发。采用与生成解耦，模型不能自己把建议变为硬规则。

代码顺序：`domain/planning/style_analysis.go` → `app/style_analysis.go` → `prompts/style_analyst.v1.tmpl` → `storage/postgres/style_analysis.go` → `server/style_analysis.go` → 前端 `ReferenceStyleAnalysis.tsx`。
