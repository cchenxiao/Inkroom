# 真实写作：接入原工作台

真实流程使用原有的 TipTap 编辑器、正文工具条、段边标注、导航、日夜主题、专注模式和底部 Agent 抽屉。已删除独立的简易写作页面及表单式正文编辑框，不再维护第二套创作台。

## 作者操作

1. 创作准备：确认立意、风格、人物世界、章纲、第一章细纲，发布初始知识。
2. 进入章节写作，左侧选择情节段，正文区生成本段候选。已采用段落与当前候选连续显示。
3. 在原文旁查看问题，直接修改 TipTap 正文后“保存并复检”，或选中文字下修改指令。作者审核在右侧完成“批准本段 → 采用本段”。
4. 右侧“整章审核”选择各段已提交版本、核对完整正文、保存章稿、启动整章复审。查看历史章稿/复审稿时，中央编辑器展示该次冻结快照并明确只读。
5. 逐条整理章末事实、确认事实知情人和证据，再确认整章定稿。模型生成的候选不能自动变成世界事实。
6. 底部 Agent 抽屉默认收起，展开后查看实际编排、修订 diff、上下文来源和查询记录。

## 接线边界

- `/workspace?projectId=project-zhuoliu&branchId=main` 默认真实；`source=demo` 保留演示入口。`planningChapterId` 使用 Go 章纲 ID，`beatId` 保留当前段落，`panel=review|assembly|bible|closed` 保留当前工作面板；旧 `stage=assembly` 书签兼容转换为整章审核面板。
- 正文编辑使用真实的版本化 `inline_edit` 人工动作接口，提交后复检；不调用 MSW 自动保存接口。
- 正文与未发送指令暂存在本标签页 sessionStorage，绑定原 run/version。正文版本变化时禁止旧编辑和旧指令提交；切段、切章、离页保护未保存输入。
- 关闭侧栏或切换侧栏 Tab 保留输入。未知结果重试保留原操作 ID；失败/中断且持有 pendingAction 的运行可以恢复原操作。
- 已采用稿本只读。重新生成会创建待审核候选，不能静默替换已提交版本；整章组稿也需要明确选版和确认。
- 后端断开显示错误，绝不回退到《浊流》ch7 演示数据。原 MSW 的 409、canFinalize、旧版本置灰行为不变。
- 尚未接线的安全暂停、正式批注/伏笔标记、全书变更传播、多分支及多作品 Go 写作明确禁用，不用 Mock 假装成功。章内前文连续传递和下一章交接仍是后续开发项。

## 前端职责

- `app/writing`：组合真实数据控制器与原有工作台组件，组织正文、右栏、底抽屉。
- `features/workspace`：公开受控的 `WritingManuscript`，复用原 `SegmentEditor`、`ManuscriptGutter`、`EditorToolbar`。只接收领域数据与回调，不读取 Go 规划 feature 内部。
- `features/prepare/writing.ts`：公开真实规划、生成、人工操作控制器，以及章稿/复审面板供 app 组合。API 调用和乐观并发逻辑仍归 prepare。
- TanStack Query 保存后端状态，真实 SSE 更新 run；本地 UI 状态与作者未提交输入独立管理。
- `docs/frontend-api.md` 演示契约未修改。真实整章定稿与事实接口分别见 [整章定稿](chapter-publication.md)、[章末事实](chapter-facts.md)。

## 书架与排版（2026-10-16）

- `/library` 与 `/library/new` 使用独立首页外壳；进入作品才显示完整作品导航。作品内的“返回书架”位于功能列表上方，不再充当一个切换后清空侧栏的功能 Tab。
- 结构目录是左侧可折叠的并排栏；选择 Beat 不关闭目录。宽屏审核与正文并排，低于 1200px 时审核改为抽屉；抽屉关闭后恢复正文焦点与操作，未提交输入保留。
- 准备页移除重复的小标题，总览章节网格使用自适应铺满；数据口径保留在可展开说明中。
- 同一个版本化 Segment 可以有多个自然段。编辑器按原换行建立段落，统一缩进和段间距；加载/保存不擅自增删换行，跨段问题引用继续高亮。
- 规划 Writer 使用 `planned_writer.v2`，取消固定 150–350 字单段限制。上下文携带已确认章纲的章目标字数与按细纲 Beat 数均分的软参考字数；自然段按情节和说话人切换组织，不按每句换行、不强制凑字数。
- 《浊流》本次已保存的第一章仍是流程试跑时确认的 600 字目标、两个 Beat；555 字已采用稿未被重新生成或改写。调整篇幅需要作者修改章纲并走原有版本复核流程。

### 原文操作与版本边界

- 选中文字会显示浮动操作；正文右键或 Shift+F10 可打开作者菜单，支持作者判断、直接修改、指令修改、重写与设定查询。没有选区时不启用依赖选区的动作。
- 从任意段进入作者审核时，段落选择与右栏切换在同一次路由更新中完成。选区绑定 segment、原文和版本，等待正确运行加载后再处理；过期引用会提示重新选择。
- 待审核候选可直接编辑并保存复检，或把原文引用带入修改要求。重写选区预填范围要求，仍需作者提交；后端现有指令接口不提供强制限定范围的局部补丁保证。
- 已采用稿保持只读，提示先通过“重新生成本段”建立新候选，再审改。当前接口不支持原地改写已采用正文，本轮不绕过该限制。
- 右栏默认显示当前稿与下一步；检查结果、候选历史、运行设置、组稿来源和完整审查依据按需展开。整章审核继续在同一工作台完成。
- 窄屏审核抽屉保留挂载，关闭后恢复焦点与正文访问；确认弹窗可正常覆盖抽屉。关闭、换页、切段的既有草稿保护不变。

### 链接与验收

- `/workspace`、`/review` 无参数旧链接恢复最近作品、分支、章节和段落；显式 URL 参数优先。真实 `/review` 进入工作台的整章审核。
- 兼容 `/book/:id/workspace` 以及书内 `#/workspace?...`、`#/review?...` 书签；刷新保留当前章节、段落及 `panel=review|assembly|bible|closed`。
- 演示章节和 Go 章纲 ID 分开恢复，不能跨作品或分支套用。带演示 `chapterId` 的旧页保持演示来源，避免从演示导航误入真实准备流程。
- 验证：38 个测试文件、129 项单元/组件测试通过；4 项 Playwright 端到端测试通过；lint、TypeScript 和生产 build 通过。构建仍提示图表包大于 500kB，属于体积提示，不影响本轮功能验收。

## 业务名称与运行进度（2026-10-16 补充）

- 底部“创作进度”默认显示准备材料、生成正文、检查正文、按需修订、作者判断、采用本段六个业务步骤。每项完成状态来自已保存材料、实际审查和作者操作；未执行分支不显示为通过。
- 完整流程图按需展开，在可见后初始化视图，避免隐藏容器测量导致偏移。图表自身导入主题样式，不依赖先访问创作准备页；正常视图保持可读字号，允许缩放、拖动与展开查看。
- 组稿下拉选项使用“候选 vN · 保存时间”，场景和情节段标题作为分组标签。实际提交仍绑定原 commitId；修改名称展示不改变选版、版本保护与重试行为。
- 作者界面优先使用已保存的章节/段落标题、材料标题和证据原文摘要；没有可识别名称时提示关联材料或原文暂缺。原始编号、校验值和内部步骤放进“技术详情（排查用）”，不能作为作者要辨认的名称。
- 这轮复用现有持久化标题及冻结原文，没有新增后端命名字段或改写旧记录。后续新增可命名业务对象，应保存业务名称或来源标题快照，与技术主键分开。
- 单段问题、整章复审、事实证据来源、知识快照、历史定稿和上下文清单采用相同规则。Beat、Critic、修复范围枚举使用对应的中文业务概念。
- API 异常保留原始响应用于排查，对作者展示可操作的中文提示；版本冲突仍保留原状态码和请求标识。来源失效的旧复审显示“需重新复审”，不再在下一步提示继续定稿。
- 验证：40 个测试文件、133 项单元/组件测试通过，4 项端到端测试通过，lint/build 通过（仍有原图表包体积提示）。另在真实写作台验证了日夜主题、进度概览、完整图展开和组稿版本标签；未执行生成、采用或定稿操作。

### 2026-10-16 正文阅读与整章审核收敛

- 正文默认 16px、1.85 行高；源文空行保留，展示高度压缩。点击正文或标题选中情节段，以墨青侧线、勾选状态和底栏名称提示；拖选文字不切换目标，未保存时维持切段保护。
- 全章按段独立读取候选稿。未采用的正文切换选中段或刷新后仍显示；读取中、读取失败与尚未生成分开显示，不能把网络错误当作空稿。
- 整章面板分为整理章稿、整章复审、历史版本。缺段时仅突出缺少审核的段落及入口，选版和诊断信息按需展开。步骤切换保留已选版本、确认状态及未决请求；来源已变的历史定稿单独折叠。
- 完整流程图改为横向布局并限制高度；滚轮滚动外层面板，拖动画布，按钮缩放，不再捕获滚轮缩放。

### 2026-10-17 写作与审核入口统一

- 真实作品左侧只保留“章节写作”入口，段落审核和整章审核作为正文旁工作面板；切换面板时导航始终选中章节写作。演示工作台的独立审核页面保留。
