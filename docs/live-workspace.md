# 真实写作页接线

已将后端现有能力从准备页移到 `/workspace`；不是把 Mock 正文发送给 Go，也不是声称全书自动写作已经完成。

## 使用

1. 《浊流》main → 创作准备：确认立意、风格、人物世界、章纲、第一章细纲，并发布初始知识。
2. 在细纲下点击“逐段写作”，或从导航进入“章节写作”。左侧目录来自 Go 章纲；尚无章纲时引导回准备。
3. 选择 Beat → 生成 → 查看正文与审稿意见 → 原地批准、下指令或亲手修改 → 提交本段。版本与操作 ID 沿用后端校验。
4. 进入“组稿与复审”：选择各 Beat 已审核提交、保存章稿，启动整章复审并记录作者决定；通过后核对事实，确认整章定稿。导航“人工审核”也打开这个工作区，不跳离创作页。
5. 展开“上下文与运行明细”查看模型材料与运行结果。后台事件使用已有真实 SSE，不启动演示事件流。

暂未接入：新增事实抽取/同步、下一章前情、多作品/多分支 Go 写作、TipTap 对真实正文的自由自动保存。当前亲手修改使用带稿本版本的人审编辑框，提交后复检；不能把演示编辑器的自动保存接口直接当成真实接口。

## 前端技术

- app 的 `WorkspaceEntry` 和 `Layout` 根据来源选择真实/演示入口。真实外壳不挂载 Mock 顶栏、正文、门禁、冲突面板和 SSE；导航也不读取演示章待办。
- `prepare/PlannedWorkspace` 是规划 feature 的公开页面入口；app 组合它，内部复用原有 `PlannedBeatWriting`、`ChapterAssembly`、`ChapterReview`。没有跨 feature 引入内部组件，未复制 API/审批实现。
- TanStack Query 保存服务端规划/正文/任务，已有 SSE 增量更新真实 run；UI 不自行合成服务器版本。
- `/workspace?projectId=project-zhuoliu&branchId=main` 默认真实；`source=demo` 为旧演示。`planningChapterId` 指向 Go 章纲章节，与旧 `chapterId=ch7` 分开；`stage=write|assembly` 决定标签页。
- 显式章节 ID 不存在时显示失效说明，不偷偷切换到另一章；非首章说明前章交接尚未接线。后端断开显示错误，不回落演示正文。
- 已访问标签页保持挂载，避免切换组稿时丢掉修改文字；待提交编辑与未知请求结果由共享轻量 Context 登记，切换章节或离页前提示，刷新也提示。未解决的请求使用原操作 ID 重试。

## 边界和后续

`docs/frontend-api.md`、MSW 的 409/canFinalize/旧版本置灰保持不变。接线阶段未新增后端契约；后续整章定稿新增独立 Go 接口（见下），未自动导入演示数据、未自动调用模型。

已接入[整章定稿](chapter-publication.md)，当前只允许作者确认无待同步事实的路径。下一步接事实候选与逐条确认，再把上一章的已确认正文/摘要交给下一章。真实长文编辑器和全书侧栏依这些契约继续接线。
