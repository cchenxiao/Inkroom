# 作者修改真实模型验收 · 2026-10-17

## 结论

真实调用 deepseek-flash，使用隔离合成材料，没有连接作品写入接口或数据库，没有修改《浊流》正文、采用记录或作者决定。生产 Writer、双评审、输出校验和批准门禁被直接复用。

最终 v6 + 按任务启用 thinking 的八个样本全部达到当前评分规则，生成稿另由开发助手逐项阅读核对。两次独立运行中的页码生成均正确。这个结果只覆盖这些固定样本，不是通用准确率，也不等于正常篇幅首章或跨章质量已验收。

## 失败与修正过程

1. v4 无推理：自动评分 4/6，但阅读生成稿发现页码重写仍错，且评审误报 addressed。因此实际语义表现只有 3/6，原评分过度信任模型自报。另一个邻段冲突被发现，但 severity/repairScope 不合法，任务失败；保留该错误而不把它算通过。
2. v5 无推理：补齐正文检查和两个留出的时间计算样本；7/8。纸张/页码生成仍保留原矛盾，评审继续误报通过。评测器的正文约束成功发现这个假阳性。
3. v6 无推理：加入观察/结论的纠错示例，单独页码复测 1/1，但随后全套仍 7/8。证明一次成功不能代表稳定修复。
4. 相同 v6 模板，仅把作者重写及其针对性一致性检查启用推理：页码复测 1/1，随后全套 8/8。保留同一模型和角色，未新增 Agent，也没有自动反复重试直到通过。

现有适配器此前固定 `thinking.type=disabled`。现在通过显式模型输入控制，且记录在调用元数据中：仅无工具、无历史消息的作者重写和 authorRequest 验收启用 thinking；普通初稿、文风检查、JSON 格式修复和工具循环沿用原模式。SDK 仅返回最终 content 和用量，不读取或存储隐藏推理。实际请求载荷和边界有本地 HTTP 测试。

依据：[DeepSeek 官方推理模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。推理模式下 temperature 不生效，所以最终实现没有把降低 temperature 当作质量保证。工具模式还要求回传 reasoning_content，本轮没有改变其协议；演示工具查证后的独立作者要求核对属于无工具调用。

## 最终样本

| 样本                           | 期望与实际结果                                         |
| ------------------------------ | ------------------------------------------------------ |
| 页码仅换措辞、编号方式未明     | needs_clarification，阻止批准                          |
| 本段页码正确、邻段仍沿用旧说法 | unresolved，阻止批准                                   |
| 本段及邻段均正确               | addressed，未误拦                                      |
| 作者质疑驱动整段重写           | 十六页后接十九页，十七、十八两页同张缺失；保留记录动作 |
| 选区余额纠错                   | 三枚交出两枚剩一枚；选区外逐字保持                     |
| 未来知识仅换措辞仍泄露         | unresolved，阻止批准                                   |
| 九点四十加半小时仍写十点整     | unresolved，阻止批准                                   |
| 九点四十加半小时改为十点十分   | addressed，未误拦                                      |

最终页码生成节选：

> 十六页之后，下一页直接跳到了十九页。……按双面连续编号，十七和十八本该是同一张纸的正反面——如今那一整张都不在了……他在笔记上记下缺失的页码：十七、十八，同一张纸。

本例明确给了双面编号设定。真实作品中编号方式尚未确定时，应继续要求澄清，不能把本测试设定自动写回作品。

## 复现

使用当前本地配置，以下命令会调用真实模型，但不会写作品数据库：

```sh
go run ./cmd/inkloom -author-revision-eval > /tmp/author-revision-report.json
go run ./cmd/inkloom -author-revision-eval -author-revision-case rewrite-pages > /tmp/author-revision-focus.json
```

未知样本在调用前报错；报告保存失败样本并返回非零退出状态，不缩小分母。自动评分还不能覆盖所有语义错误，生成正文仍需人工复核。

## 后续验收

本轮完成“修改要求落实”的针对性真实验收。仍需完成正常目标篇幅的整章生成/局部修改验收，以及事实提取的真实调用验证和首章作者定稿，再推进下一章交接。旧事实提取失败缺少原始诊断，不能用本轮结果宣称其根因已修复。
