# 长文审核与保留正文复检 · 2026-10-17（第三轮）

## 已交付

- 审核失败回执增加稳定的 `failureCode`，区分输出截断、等待超时、预算耗尽、证据定位不合法与中断。右栏显示“检查未完成”，不直接展示供应商异常，也不把空结果当通过。
- 新增“保留正文，重新检查本段 / 整章”。作者主动触发新检查；复用保存正文和原作者修改要求，重新冻结当前材料，不调用 Writer，不自动修订、不自动批准。未保存正文或未发送指令存在时禁用入口。
- 整章复检保持全部情节段及顺序，校验来源版本与当前章稿版本一致、情节段和场景与当前细纲匹配。单段来源不能冒充整章，旧章稿不能覆盖新版；重试沿用已有请求幂等机制。
- 模型调用记录的 `success` 不再把 `finish=truncated/refused` 当成功。解析链路正确累计用量的可信标志，不因为走了一次解析就丢失 `Known`。

## 实验审核的实现与限制

实验仍默认关闭，服务保持 `INKLOOM_EXPERIMENTAL_CONTINUITY=false`。本轮未变更《浊流》的正文、采用记录或人工决定。普通事实核对、作者纠错与其验证继续使用原策略。

材料超过 3000 个非空白字符（包括前后邻稿）时，将检查任务分为物件/数量与人物/动作两次；两次都保留全部原文、中间动作和只读邻稿边界，不按篇幅裁剪证据。短稿一次检查。每次仍受 8192 输出、60 秒单次超时与原总调用/token Guard 限制，任一检查失败则整体不返回已完成的衔接结论，不自动增加预算或无限重试。

模型只返回两处自然段证据编号，程序恢复原文引句并定位到较后的可修改证据。若后处是只读邻稿，则定位前处可修改证据并要求作者裁定。未知编号、倒序、两处均只读、重复意见和遗漏核对对象继续拒绝。跨两次检查的相同证据去重。当前模板 `hard_consistency.v13`、契约 `continuity_pairs.v2`。

保留的实验配置是物件检查用推理、人物检查用普通模式；全面关闭推理的试验出现漏检，已经撤回。**这不是已通过验收的质量策略**：物件检查仍可能推理截断，普通人物检查有过度判错风险，不能自动开启。

## 一致性检查额度调整为 30,000（2026-10-17，后续调整）

按作者要求，将一致性检查的默认值、本地运行配置和示例配置从 16,384 调到 30,000。此前测试报告保留原实验参数，不改写历史结果。仅 hard_consistency / chapter_consistency 生效；其他角色默认仍为 8,192，单次审核超时仍为 90 秒，运行总额度默认 128,000 / 14 次。

该值经 Guard 预留，再由 DeepSeek 适配器写入请求 max_tokens。供应商达到生成上限返回 length，系统判作检查未完成，不将半截 JSON 当作通过，也不因截断自动追加调用。总运行额度在调用前保守估算（输入 UTF-8 字节加最大输出等），预算不足则不发请求，结束后有已知 usage 才按实际用量结算；它不是逐 token 的运行中熔断。时间限制独立生效，90 秒或父流程截止时间先到就取消客户端请求，不保证供应商端同步停止计算/计费。

核对 DeepSeek Chat Completions 官方文档：30,000 在当前公开 max_tokens 可设范围内；这不代表长章质量已验收，也不保证 90 秒内完成。本轮仅执行本地配置、预算及适配器请求测试，不发起付费长章生成。
