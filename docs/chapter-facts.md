# M0.4c5b 章末事实候选与作者确认

入口：真实章节写作 → 组稿与复审 → 作者批准复审 → 整章定稿中的“章末事实整理”。

## 使用

- “从章稿提取候选”调用事实整理模型，只提出带逐字原文证据的候选；“我来整理事实”直接建立人工批次，不调用模型。
- 每条可确认为新增事实、排除、保留关联的旧事实，或要求修改正文。确认新增事实时可改写陈述并指定知情角色；勾选表示作者确认该段证据足以证明角色已在该时点获知。不选则不会进入任何角色的已知材料。
- 台词或不确定候选不能直接确认为世界事实。作者若核对出明确发生的事件，可另行补充，指定原文段落、逐字引文和陈述。模型空列表不代表没有新增事实。
- 关联旧事实时并排显示旧说法，不直接覆盖。保留旧事实需说明依据（如台词谎言/角色误解）；若确实是正文错误，选择要求改稿会持续阻断定稿，需改稿、复审后重新整理。全局改变旧设定及跨章传播仍属后续变更流程。
- 可保存尚未处理完的决定；有遗漏或要求改稿的条目不能定稿。处理完成后，作者最后确认无遗留冲突，再提交整章定稿。

## Agent 技术

`ExtractChapterFacts` 使用独立 `chapter_facts.v1` 提示词与 JSON Schema，经现有 Guard、结构化解析和引用校验链执行。预算/超时仍受配置约束，格式修复不会自动批准事实。输入来自已批准复审的不可变章稿和它引用的知识快照，不接受浏览器上传的“可信原文”。这是作者视角的整理任务，能看完整基础知识；它的输出不直接给 Writer。

模型输出最多 16 条，作者另可补 8 条。每条区分 event / statement / uncertain；evidence 必须指向本批次正文且引文逐字存在，relatedFactId 必须来自冻结知识。程序只能证明出处和结构有效，不能证明模型概括真实、候选齐全或没有漏掉语义冲突，最终由作者核对。

`BuildChapterFacts` 为纯函数：核对候选/决定/引用/角色 ID → 生成新增事实包和阻断原因。知情角色只来自作者选择，不由模型补全；时间沿用证据段的冻结故事时间，来源保留 commit、segment 和稿本版本。本轮不支持另外指定更晚的获知证据；这种条目暂不声明该角色知情。

## 版本与存储

迁移 019 新增候选任务、模型调用和作者决定版本。任务按 running → completed / failed / interrupted；服务重启不自动重发模型调用。相同请求 ID 相同内容返回原结果，内容变更拒绝；手动重新整理产生新批次，旧批次不能继续采用。

保存决定采用 expectedVersion，后台轮询不会覆盖未保存输入。网络结果未知时保留完整原请求重试；章稿/复审/候选批次变化后旧操作不能生效。整章定稿事务再次核对最新候选与决定版本，不能勾选“无遗留”绕过正在提取、失败、未保存或未处理完的候选。

另一个窗口定稿时，本窗口保留未保存文字和未知结果请求，转为只读供复制或主动放弃。原请求仍可重试取回已保存回执；未成功保存的操作不能改写已定稿版本。

**章末输出与章前输入分开：** 定稿记录新增 `factReview` 和 `factSelection`，保存模型候选、调用、排除理由、人工补充、逐条决定与 `package`。事实包包含 `baseKnowledge` 和新增事实；这是一份随整章定稿冻结的增量，不更新当前 `knowledge_heads` 或检索目录。否则同步本章结果会立即让本章自己的输入版本失效。下一章交接阶段将明确消费“基础知识 + 前章已定稿事实包”，仍按时点/POV 投影；本轮不宣称当前 Writer 已消费新增事实。

已有的无候选人工确认定稿路径保留；一旦为这份复审建立候选批次，就必须完整处理该批次。定稿后禁止改动其事实决定；修改须建立新的章稿/复审，不改写历史回执。

## Go 接口

前缀 `/api`；前端走 `/go-api`，Mock `docs/frontend-api.md` 不变。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| POST | `/planning/chapter-fact-jobs` | `{requestId,reviewId,inputDigest,mode:model或manual}` → job |
| GET | `/planning/chapter-reviews/:id/facts` | 当前候选批次、最新作者决定、current/published/block |
| POST | `/planning/chapter-fact-selections` | `{requestId,jobId,expectedVersion,manual[],decisions[]}` → 版本化决定 |
| POST | `/planning/chapter-publications` | 在原定稿请求上增加 `factJobId/factVersion`；有候选时必须匹配 |
