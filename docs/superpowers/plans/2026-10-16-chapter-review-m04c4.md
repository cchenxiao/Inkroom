# M0.4c4 整章复审与作者决定

沿用作者已认可的分模块路线，在 M0.4c3 组稿基础上继续；不自动提交上一轮代码。

## 范围
- 对已保存且来源仍有效的最新章稿异步复审。两路独立冷读：章内一致性/衔接、重复/语言。共享调用预算；固定完整输入、不自动截断正文；记录调用。
- 新的整章审稿提示词与结构化契约，段落 ID 在章稿内唯一；区分原文 passage 与各段冻结事实 fact，不把台词、误解或作者计划提升为事实。
- Finding 必须引用实际原句与证据。模型漏审仍可能发生，空意见不宣称查证完备。
- 作者对最新有效报告确认通过或记录返工要求。通过复审仍不等于最终定稿/事实同步完成，本阶段不自动改稿、不接下一章前情。
- 当前来源变化/新章稿/新复审会作废旧审批资格；超时结果未知沿用请求ID查询回执；服务重启标记中断，不自动重发收费请求。
- UI 在准备→大纲→整章组稿内完成，展示版本、状态、证据及调用记录。失败不是无问题通过。

## 取舍
- 使用已有异步任务和模型 Guard/parse 模式，避免把组稿伪装为既有单 Beat Run。
- 全章跨段自动修订留后续，作者先回对应 Beat 改稿、复审提交、重新组稿。事实级 P3 等待人工判断也阻止“确认通过”，不能当作已解决。

- 前端新用例覆盖失败门禁、未知结果原请求重试、409 清除确认。默认高并发下两个旧 UI 用例重复出现 5 秒超时；限制两个 worker 后全量通过，测试执行累计耗时从 52 秒降至 7 秒。已在 Vite 测试配置中限制并发，默认 pnpm test 最终通过 29 文件 / 109 测试；没有放宽超时或修改断言。
