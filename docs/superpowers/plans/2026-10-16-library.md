# 作品层实现计划

目标：书架 → 作品总览 → 某章写作；四步向导可编辑、确认、回退、保存本地演示草稿。保留旧六路由，用 URL 查询参数携带作品/章节，旧无参数书签仍打开浊流。

边界：不改 Go 契约；新作品全部 MSW + 浏览器本地演示存储，显式标识。作品层数据独立，不能把另一本书的请求回落到浊流。原 409/canFinalize/审批失效逻辑保留。向导上游更改使下游待确认；只发布锁定的版本到总览。新作品暂不支持真实 AI 审核，手动正文编辑与试写分支为 Mock。

- [x] 领域契约、作品与向导 Mock 存储/候选/校验/隔离（主代理）
- [x] 书架与作品总览 UI（独立任务）
- [x] 新建向导与分步编辑器 UI（独立任务）
- [x] 全局路由、作品上下文、六页归属、真实后端边界（主代理）
- [x] 少量关键测试：跨作品隔离、向导锁定与失效、草稿恢复；现有测试/构建检查；浏览器验证

沿用现有当前开发分支，保留上阶段 M0.1a 未提交改动。按用户完整需求直接实现，UI 两部分按 dispatching-parallel-agents 技能分工，统一契约后互不编辑同一文件。

验收：新增 11 项关键交互/隔离检查（含向导、总览、自动保存），原测试保留；浏览器完成新建、草稿退出/刷新恢复、四步锁定、首章试写、书架字数更新。
