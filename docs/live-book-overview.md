# 真实书架与作品总览

《浊流》main 的 `/library` 主卡和 `/book/project-zhuoliu` 默认读取 Go/PostgreSQL。演示作品收在书架独立折叠区，新建向导仍明确标为演示。现有 Mock 接口与 `docs/frontend-api.md` 不变。

## 数据口径

- 新增只读 `GET /api/planning/overview`，前端通过 `/go-api/planning/overview` 读取。暂只支持既有 `zhuoliu/main` 工作区；书名仍为工作区固定名称，未实现作品改名/多作品创建。
- 规划、风格、人物、后续计划取已保存版本。仅展示依赖仍有效的已确认人物和风格；章纲未确认或来源变化会明确标为待复核。
- 字数只统计目前可采用的、已审核提交的 Beat 原文，不含未提交候选和旧版本，含标点、不含空白。整章和 Beat 不重复计数。
- Beat 分母仅含当前已确认、有效细纲中已展开的 Beat，不推算未展开章节。定稿数只统计版本仍有效的整章定稿；历史定稿单独提示。
- 审查摘要来自当前整章复审，不提供假分数。后续情节计划不冒充已埋设伏笔；人物弧光不显示推算完成百分比。
- 空库显示零正文、零章节、待创作准备；后端出错显示错误，不切回演示内容。

## 导航

主按钮按真实依赖引导到立意、风格、人物世界、章纲、知识发布或真实写作页。工作台使用 `planningChapterId`，不使用演示 `ch7`。第一章已有足够可采用段落时进入组稿与复审；其他章进入细纲准备，跨章写作仍未开放。

真实书架、总览与《浊流》main 准备页采用共用外壳，但不挂载演示章查询、待办数字、分支操作和事件流。每五秒刷新总览，返回窗口时重新读取。

## 实现与验证

后端复用规划头、组稿候选资格、整章复审及定稿有效性规则。总览读取与写入共享规划锁，不新建业务记录、不运行模型。前端使用独立领域摘要类型和 TanStack Query，不跨 feature 引用准备页内部组件。

关键验证：空数据库不制造进度和作品记录；有效定稿计入、历史定稿排除；真实书架到准备的空状态路径；真实章节 ID 跳转；服务失败时不回落演示数据。本轮不触发付费模型调用。

2026-10-16 验证：前端 117 项测试、TypeScript、lint、生产构建通过；Go 全量测试（含独立 PostgreSQL）和 vet 通过。独立代码检查无重要问题。本地服务已更新；浏览器实查书架 → 真实空总览 → 立意准备，空库正确显示 0 章/0 字，未导入演示数据或调用模型。
