# 墨枢 Inkloom 产品设计

依据：[原始技术架构与详细设计](/Users/chen.xiao/Downloads/01-技术架构与详细设计.md)。产品目标与原稿一致：作者确定方向，系统执行多角色创作、审查和有限返工，作者在关键节点审核，也能随时暂停接管。

## 1 完整创作流程

| 环节 | 作者操作 | 系统处理 | 可见产物 |
| --- | --- | --- | --- |
| 立意与定调 | 输入故事想法、类型、主题、篇幅、POV 与文风偏好 | 提出 Logline 和核心冲突，初始化 StyleProfile | 可选方向与项目创作要求 |
| 人物与世界 | 修改、确认人物小传和世界规则 | 生成人物 want/need/flaw/弧光及 VoiceProfile | 人物卡、世界规则、初始 Story Bible |
| 大纲与节拍 | 选择结构、确认转折与章节计划 | 拆为 Chapter → Scene → Beat | 可编辑大纲和场景节拍 |
| 章节创作 | 选章启动，设置本次限制 | 装配上下文、按 Beat 生成、并行审查、分级返工 | 正文、节点进度、问题和修订记录 |
| 人工审核 | 批准、批注、直改或返回规划 | 暂停等待，按决定恢复指定流程 | 审批卡、diff、未解决问题 |
| 定稿与续写 | 确认正文及需要裁定的设定变化 | 对齐 Bible，提交版本，更新记忆 | 定稿、事实变化、摘要与下一章入口 |
| 全书统稿 | 选择全稿检查范围与修订方向 | 检查跨章风格、人物声音、伏笔及连贯性 | 全稿报告、分项修订、导出 |

用户可导入已有设定、大纲或正文，不必从立意重新开始。已确认方向成为后续约束；改方向时走变更影响流程。

## 2 自动推进与人工接管

**系统自动执行**：上下文装配、初稿、已启用 Critics、问题聚合、授权范围内的分级修订和复检。默认自动返工 2 轮，超限进入人工处理，不要求作者逐步点击每个节点。

**需要作者决定**：立意和大纲锁定、章末定稿、重大结构调整、事实冲突、超过返工上限、跨章修改方案。P3 建议可保留；对误报的否决需要记录理由并重新核对门禁，不能用“批准”静默跳过真实设定冲突。

作者随时可暂停、批注或编辑。暂停后保留当前产物；恢复时从相应节点继续。正在进行的模型调用可能完成或被取消，迟到结果不能覆盖作者的新修改。

## 3 产品页面与信息组织

| 页面 | 展示内容 | 核心操作 |
| --- | --- | --- |
| 项目与创作准备 | Logline、StyleProfile、人物卡、世界规则、层级大纲 | 生成建议、编辑、锁定、选择章节 |
| 章节工作台 | 左侧章/场景/Beat 结构，中央正文稿纸（视觉主体），右侧系统信念 Story Bible（人物/时间线/伏笔/规则/信息差/风格），底部可上拉「Agent 工作台」抽屉（编排流 / 评审与冲突），顶部门禁分与运行状态 | 启动、暂停、定位问题、批注、直改、裁决冲突 |
| 人工审核 | 当前版本、各 Critic 结果、历轮 diff、待裁定问题、事实变化 | 批准、要求修改、返回 Beat/大纲 |
| 变更与冲突 | 修改前后、影响章节、依赖原因、双方证据 | 选择修复范围，裁决正文或设定 |
| 版本与试写 | 历史定稿、分支、比较结果 | 恢复历史、创建试写、选择采用版本 |
| 全稿与评测 | 全稿问题、风格趋势、伏笔状态、成本与质量报告 | 统稿、查看对比实验、导出 |

这些是模块完成后的信息组织，不要求首期同时建设所有页面。

## 4 章节工作台的操作闭环

1. 作者选定章纲与 Beat，核对人物、规则、风格及待回收伏笔，点击“开始本章”。
2. 系统展示“装配上下文 → 初稿 → 审稿 → 修订”的进度。作者可查看使用了哪些前情，不必阅读 Prompt。
3. 审稿问题按 P0～P3 分类，显示原文位置、证据、影响和处理方式。自动修订保留前后对比。
4. 达到门禁或需要裁决时进入 Human Gate。作者可批准、下批注，或直接改正文。
5. 人工修改后的稿件重新接受相关检查；旧稿审查结果不能冒充新稿已通过。
6. 系统提取设定变化并对齐 Bible。新增冲突返回人审；无冲突则保存正式版本并更新记忆。
7. 下一章使用已确认正文和设定。摘要、检索更新尚未完成时显示状态，不使用过期内容误导续写。

审核绑定具体稿本。作者同时在另一处修改了正文时，旧审批失效，页面要求查看新 diff 后再决定。

## 5 三种人工修改

### 改设定或大纲

例如删除一个配角。系统先列出出场章节、人物关系、承载的伏笔和后续情节，再提供合并人物、替代角色、连带删改等方案。作者选择后才执行相关重写；其他章节保持原状或标为待复核。

### 直接改正文

作者修改后立即保存候选。系统分析文字与事实变化：表达调整更新局部检查；涉及人物状态、事件或硬设定时，展示与 Bible 的差异以及对其他章节的影响。

人工正文代表作者意图。若其中是台词谎言、人物误解或暂未确定的设定，作者可以明确标记，系统不直接把它当作全书事实。

### 只下批注

例如“这里让主角失态，但不要改变事件结果”。系统生成局部 patch 和 diff，作者采用、调整或放弃；采用后复检受影响内容，并记录 ChangeSet。

三种路径统一形成“修改 → 影响分析 → 同步或裁决 → 复检”。界面展示已处理和仍待处理的影响项。

## 6 风格与质量的交互

保留风格画像、人物声音、AI 味多信号检查和质量门禁。用户看到的是具体表达问题、原文热区、风格偏差和建议，而非只有一个总分。

项目允许配置风格目标和已校准阈值；系统展示每项分数依据。未校准指标先作为提示，避免把某个常用词或低句长波动直接判成质量不合格。作者的误报反馈进入后续评测样例。

统稿按章节或场景提出修订，保留动作场景和抒情场景的节奏差异。人物声音对照人物卡检查，不把全体对白统一成一种风格。

## 7 分模块交付

| 阶段 | 用户能完成什么 | 本期交互范围 |
| --- | --- | --- |
| M1 单章闭环 | 给出本章 Beat 和基础设定，得到经过审查、有限返工、人审确认的章节 | 创作要求、章节工作台、审批和 diff；规划可人工录入 |
| M2 跨章记忆 | 连续写作，查到角色、时间线、伏笔和引用前情 | 设定管理、上下文来源、章末记忆确认 |
| M3 人机共创 | 改旧稿或设定，查看影响、解决冲突、试写另一版本 | 三类修改完整流程、冲突队列、历史与分支 |
| M4 评测与成本 | 比较模型与流程效果，观察返工和成本 | 评测报告、门禁配置、运行追踪 |
| M5 打磨 | 检查并统一整本小说，导出最终稿 | 完整多维审查、人物声音与全书统稿 |

第一轮验收围绕一章：系统自动审查并返工，超限能接管，意见能定位，修改能对比，人审能暂停恢复，定稿有版本。后续模块沿原设计逐步补齐，不缩减为三个独立生成按钮。
